# Структура проекта

.
├── main.go            # HTTP-обработчики и маршруты
├── shortener.go       # Бизнес-логика (хранилище, валидация, генерация)
├── shortener_test.go  # Модульные и интеграционные тесты
├── go.mod             # Зависимости
└── README.md          # Документация


Проект демонстрирует правильную архитектуру, обработку ошибок, конкурентную безопасность и покрытие тестами.

---

## 📋 Особенности реализации

### 🧠 Бизнес-логика (`shortener.go`)

- **Потокобезопасное хранение** — используется `sync.RWMutex` для защиты мапы с URL-ами.
- **Валидация URL** — проверка схемы (`http://` или `https://`) и наличия хоста.
- **Генерация коротких ID** — длина от 6 до 8 символов (алфавитно-цифровые).
- **Предотвращение коллизий** — при генерации ID выполняется проверка на уникальность.

---

### 🌐 HTTP-обработчики (`main.go`)

- **Валидация методов** — только `POST` и `GET` разрешены для соответствующих эндпоинтов.
- **Корректные HTTP-статусы**:
  - `200 OK` — успешное получение ссылки.
  - `201 Created` — ссылка сокращена.
  - `400 Bad Request` — невалидный URL или тело запроса.
  - `404 Not Found` — короткий ID не найден.
  - `405 Method Not Allowed` — неподдерживаемый метод.
- **JSON-ответы** с полем `error` для удобства интеграции.

---

### 🧪 Тесты

| Тип теста | Описание |
|-----------|----------|
| **Table-driven** | Параметризованные тесты для бизнес-логики (валидация, генерация, сохранение). |
| **httptest** | Тестирование обработчиков без реального запуска сервера. |
| **Под-тесты** | Использование `t.Run()` для изолированных сценариев. |
| **Конкурентные тесты** | Проверка `RWMutex` при одновременной записи и чтении. |
| **Интеграционные** | Полный цикл: создание → получение → проверка данных. |
